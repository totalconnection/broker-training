# Freightskills GPT operations

Native /gpt is the embedded Freightskills program expert. The model is fixed to gpt-4.1-mini-2025-04-14 and has the hosted web-search tool available. The prompt requires search for current, changeable, or consequential information, especially regulatory and safety questions; each response is capped at two hosted tool calls. Search and curriculum retrieval stay behind the conversation: members do not see source IDs, references, citations, archive controls, or knowledge-review UI. Attachments, external actions, retries, and model selection are not offered.

Conversations are server-owned records in `workspace_items`, scoped to the authenticated member. The API creates a stable conversation ID, saves both user and assistant turns, lists recent threads, and reloads a selected conversation. Up to 16 recent saved turns are sent to the model for a response; up to 100 turns remain stored per conversation. The browser never supplies authoritative history. This mirrors the persistent thread structure used by Sal while keeping Freightskills read-only.

## Private knowledge

The public GitHub repository must never contain data/knowledge. The library is stored as knowledge/library.json in the portal's existing private Railway bucket. It currently contains 99 transcript sources plus the owner-approved objection example. No claim is made that all source text is current or privacy-reviewed. Owners can search all sources. Students search only approved sources. Source review and approval are available to administrators on /gpt. Publishing a lesson does not automatically approve its transcript. Vimeo links and PDFs are not automatically transcribed or indexed. New knowledge requires updating the private library; a self-service import workflow is not implemented yet.

The initial retrieval engine searches bounded transcript passages by terms. It does not yet use semantic embeddings. Retrieval uses the current message plus recent user messages so short contextual follow-ups can still find relevant material. Only passage text is supplied to the model as private background knowledge; source IDs and titles are not included in the model request. The prompt forbids exposing the retrieval mechanism or showing references. The separate `/api/knowledge` owner workflow remains available for administrative review but is not rendered anywhere in the member chat.

## Enablement

OPENAI_API_KEY must exist on the broker-training production service. AI_ENABLED must be exactly true. Missing keys or a disabled flag fail closed. AI_MONTHLY_BUDGET_USD defaults to 50; malformed or negative values disable paid requests through a zero budget. The API key is server-only. Local demo does not make paid calls.

## Cost controls

PostgreSQL serializes request reservations across all instances. Each request reserves 30,000 microdollars ($0.03) before calling OpenAI. Reservations are intentionally not refunded; successful actual token cost is tracked separately. This conservative allocation avoids relying on provider billing delays or retry assumptions. Failed/uncertain requests retain their reservation. Input text is capped at 30,000 UTF-8 bytes; output at 1,500 tokens. At verified standard model rates ($0.40/M input, $1.60/M output), the reservation covers this bounded text-only request with overhead margin. Recheck rates before changing models or prices.

Limits: 100 paid requests per user per UTC calendar month, 10 per UTC day, one pending request per user for up to two minutes, two hosted tool calls per response, and a 45-second provider timeout. A stale pending request remains charged against the budget. The request body is capped at 30,000 bytes and the combined instructions, chat context, and retrieved excerpts at 50,000 bytes. A conversational request can call the model even when no teaching passage matches; the prompt then limits unsupported Freight Skills attribution and substantive freight advice. Hosted web search has a separate per-call charge in addition to token usage; the conservative request reservation remains the hard application budget allocation and must be reviewed against current provider pricing before launch. All admins also count against usage limits. This budget covers this endpoint's model and web-search requests only, not unrelated API use, storage, hosting, or separately authorized evaluation runs.

## Validation

Tests exercise source retrieval, default unapproved archive, conversational prompt requirements, quota boundaries, busy-request rejection and reservation arithmetic. Full concurrency testing against production PostgreSQL and authenticated multi-turn end-to-end checks remain pending permitted access. Live model evaluation requires the configured OpenAI key and uses scripts/evaluate-gpt.ts. Before public launch, Luis should review a broader set that includes both single-question accuracy checks and multi-turn conversations. The first three live checks are a smoke test, not a complete quality evaluation.
